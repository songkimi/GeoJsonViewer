# GeoJsonViewer · 迷你 GeoJSON / shapefile 查看器

一个 Windows 桌面小程序（C# + WPF）：打开 `.geojson`、`.json` 或 `.shp`，把点、线、面画到画布上，
支持滚轮缩放、左键拖拽平移、鼠标悬停查看属性。

它是一个练手项目：存在的目的是把「基准转换 → 投影 → 屏幕映射」这条流水线亲手走通一遍。
它不打算替代任何地图软件，也不追求性能。

## 功能

- **打开**：工具栏 `[打开…]`，认 `.geojson`、`.json` 与 `.shp`（`.shp` 必须配同名的 `.dbf`；
  `.shx`、`.prj`、`.cpg` 可选）。`.shp` 带 `.prj` 时，程序会从声明里认出源基准，自动选好「源基准」下拉框。
- **自动适配**：打开后自动 fit —— 全部对象可见、居中、四周留 20 px 边距。
- **画法**：点是圆点、线是折线、面是半透明填充。
- **投影**：工具栏里选 `线性` / `Web 墨卡托` / `高斯-克吕格`，切换后立即按新投影重新 fit。
  高斯-克吕格模式下可以再选**椭球**（CGCS2000 / WGS84 / 北京54 / 西安80）与**分带宽度**（3° / 6°）；
  中央经线不用手填 —— 按数据经度范围自动吸附到标准带，数据跨出本带时状态栏会给出提示。
- **源基准**：默认按 `CGCS2000` 处理，见下面「大地基准」一节。
- **缩放**：滚轮缩放，范围 `0.2× ~ 20×`，**以鼠标位置为锚点**（鼠标下的那个点保持不动）。
- **平移**：按住左键拖拽，拖多少走多少。
- **悬停**：鼠标靠近某个对象时弹出提示框，显示它的名字（`name`，没有就 `title`，再没有就「未命名的点/线/面」）
  以及最多 3 个属性；提示框贴不到右边/下边时会自动翻到另一侧。
- **状态栏**：左边是 `文件名　·　N 个对象[　·　跳过了 M 个不支持的对象]　·　缩放 x.xx×　·　投影：投影名称`
  （高斯-克吕格还会带上椭球、带宽与中央经线）。数据跨带、`.prj` 认不准基准、文件缺经纬度范围时，末尾会追加一句警告。
  右边是光标处的经纬度：线性模式下平面值就是经纬度，墨卡托模式下按同一读数近似显示，
  高斯-克吕格模式下用反算换回经纬度；鼠标挪进东邻带的范围时，再多给一条
  `东邻带中央经线 x°：(东 …m，北 …m)` 的换带读数。
- **出错不崩**：文件不存在、JSON 语法错、空 `FeatureCollection`、shapefile 缺件，都在绘图区中央显示一行提示
  （读不了的文件显示「打开文件时出了意外：…」），例如「这个文件里没有可显示的对象」
  「JSON 格式不对（第 9 行第 3 个字符附近）：这个文件不是合法、完整的 JSON。」

## 大地基准（源基准）

工具栏的 `源基准` 说的是**文件里的坐标属于哪套大地基准**（它和椭球不是一回事）。
选中之后，程序先用七参数（布尔莎模型，位置矢量约定 `EPSG 9606`）把坐标转到 `CGCS2000`，再送进投影流水线；
`北京54 → 西安80` 这种「两头都不是 CGCS2000」的组合会走两腿中转（中间必须留一次经纬度与大地高）。
它是纯经纬度上的变换：平面坐标、缩放、fit 都在这之后才发生，所以切换源基准会把整层数据重算一遍。

代码里自带的 `北京54 → CGCS2000`、`西安80 → CGCS2000` 两组参数是 **示例参数**，只够把七参数这条流程跑通。
真实七参数是分区域的测绘成果，用之前必须按测区获取，并在代码或数据里写明来源。

## 快速开始

需要 **.NET 10 SDK**（目标框架 `net10.0-windows`，只在 Windows 上跑）。

```powershell
dotnet run                              # 启动窗口
pwsh -File .\build.ps1 build            # 只编译
pwsh -File .\build.ps1 selftest         # 不开窗口，跑一遍自检
```

`build.ps1` 只是把 dotnet 的临时目录（`.dotnet-home`）和 NuGet 包目录（`.nuget-packages`）指到项目文件夹里，
免得去写 `C:\Users\...` 下面的目录；本机终端直接 `dotnet run` / `dotnet build` 效果一样。

自检（`GeoJsonViewer.exe --selftest`）不开窗口，把 181 项检查过一遍：GeoJSON 解析与宽容策略、投影换轴、
fit 与屏幕映射、缩放锚点、拉窗口、悬停命中、退化输入、高斯-克吕格正算 / 反算 / 自动选带 / 换带、
七参数基准转换与 `TransformLayer`、shapefile 读 `.shp`/`.dbf`、按扩展名分派、`.prj` 解析与「`.prj` → 源基准」建议，
逐项打印实测数值。退出码：`0` 全部通过、`1` 找不到示例数据、`2` 还有未实现的方法、`3` 抛了异常、`4` 有数值不符。

## 支持的格式

### GeoJSON

| `geometry.type` | 支持情况 |
|---|---|
| `Point` / `LineString` / `Polygon` | 支持 |
| `MultiPoint` / `MultiLineString` / `MultiPolygon` | 支持：1 个要素展开成多个对象，属性共用一份（飞地之间不会被连出一条线） |
| `GeometryCollection` | 不支持，跳过并计数 |
| 其他未知类型 | 跳过并计数 |

宽容策略——不因为一个坏元素拒绝整个文件：

- `coordinates` 里多余的第三个数（高程）忽略；坏点（不是数字、NaN、无穷、不够两个数）丢掉该点，其余照画；
- `properties` 的值不管是数字、布尔还是 `null`，统一转成字符串；嵌套对象/数组保留原始 JSON 文本；
- 单个要素缺 `geometry`、缺 `coordinates`、`type` 不在白名单 → 计一次「跳过」，其余对象照常显示；
- 只有整个文件都用不了时才报错（文件不存在、JSON 语法坏、根不是 `FeatureCollection`）。

### shapefile

- `.shp` 必须配同名的 `.dbf`；`.shx` 可选
  `.prj`（坐标系声明）与 `.cpg`（属性表编码）也都可选。
- 几何：`Point` / `LineString` / `Polygon` 及其多部件版本；多部件各自拆成一个对象，`.dbf` 属性共用一份。
- `.dbf` 编码：先看 `.cpg`，其次看 dBASE 头里的语言驱动字节；GB18030 这类非 Unicode 编码已经注册进程序，
  读取选项（`ShapefileReadOptions.EncodingName`）里也能显式指定编码名。
- 属性值转字符串：数字去掉多余小数位、日期统一成 `yyyy-MM-dd HH:mm:ss`、空值给空串。
- 几何不合规时默认走「快速修补」（`QuickFixInvalid`）：坏掉的环尽量修，修不了的记录跳过；
  被跳过多少条用 `.shx` 的记录总数对账（库本身不报告丢弃数；没有 `.shx` 时按 0 算）。
  `.shp` 里空形状的记录也直接略过。
- `.prj` 只用来**猜源基准**，不参与坐标换算：声明是投影坐标系（单位米）、或认不出基准时，状态栏会给提示，
  对应「这是投影坐标系（坐标单位是米），不参与基准识别」「无法识别这套基准，请手动选择」。
- 坐标必须是经纬度（度），`(X, Y)` 直接当 `(经度, 纬度)` 读，不做投影反算。
- 面的洞会被一起填实（只取外环，与 GeoJSON 同一条限制）；`GeometryCollection` 之类的混合类型跳过并计数。

## 示例数据

`Samples/` 里的文件会跟随程序一起复制到输出目录，也是「打开…」对话框的默认位置：

| 文件 | 内容 |
|---|---|
| `beijing-shanghai-guangzhou.geojson` | 手工测试数据：北京、上海、广州 3 个点 + 1 条线 + 1 个三角形，共 5 个对象 |
| `贵州省.geojson` | 真实数据（阿里 DataV）：9 个市州、19 个多边形、5590 个点，全是 `MultiPolygon`，展开成 19 个对象 |
| `中华人民共和国.geojson` | 真实数据（阿里 DataV）：477 个行政界线要素（地级市为主，含部分区县）、16.4 万个点、3.8 MB，展开成 1313 个对象 |
| `empty.geojson` | 空 `FeatureCollection`：应显示「这个文件里没有可显示的对象」 |
| `broken.geojson` | 坏 JSON：应显示带行列位置的中文提示（第 9 行第 3 个字符附近） |
| `skipped.geojson` | 各种不支持/坏数据的样本：应读成 5 个对象、跳过了 7 个 |
| `one-point.geojson` | 只有一个点：点应落在视图中心，尺寸正常，不会被 fit 放大成占满屏幕的巨点 |

`TestData/` 下另有 Natural Earth 的 shapefile 与一次性探针工程，都在 `.gitignore` 里，不进版本库。

## 已知限制

- 投影只支持三种（线性、Web 墨卡托、高斯-克吕格）；国内常见的 GCJ-02（火星坐标）数据直接画会有几百米量级的偏移。
- 一张图只能用一个中央经线：宽范围数据按「单带加宽」处理，两端会出带（状态栏有提示），
  需要严格分带时得先做换带或多带分幅。
- 面**只画外环**：`Polygon` 里有洞（内环）时，洞会被一起填实；shapefile 的面同理。
- 不处理 `GeometryCollection`。
- shapefile 只读不写；坐标必须是经纬度，东偏 `y` 上带的「带号前缀」（如 `20500000`）不会自动剥。
- 没有空间索引：渲染和命中测试都遍历全部对象，几万个点还行，百万级需要网格 / 四叉树。
- 没有瓦片、没有网络、没有图层管理、没有属性编辑、没有导出。
